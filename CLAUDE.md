# CLAUDE.md — LATW (LISA Analysis Tools Workshop)

Tutorial/workshop repo for the LISA Analysis Tools stack. LISA Analysis
Tools–wide coding rules live in
[`LISAanalysistools/docs/conventions.md`](https://github.com/lisa-analysis-tools/lisa-analysis-tools/blob/dev/docs/conventions.md)
(clone LAT as a sibling — `install.sh` lays the repos out side by side).

## Branch policy (THE rule of this repo)

- **`main`** must run against the latest **pip-installable releases**:
  `lisaanalysistools`, `eryn`, `gbgpu`, `bbhx`, `fastemriwaveforms`,
  `fastlisaresponse`, `gpubackendtools`. Never introduce dev-only APIs on
  `main`.
- **`dev`** must run against the **development stack** installed by
  `LISAanalysistools/install.sh` (GPUBackendTools@spline, Eryn@dev,
  LISAanalysistools@dev, BBHx@dev, GBGPU@dev, FastEMRIWaveforms@gpu_backend,
  phentax; lisa-on-gpu is deprecated).
- If you change a dev-branch API in any stack package, fix the LATW `dev`
  tutorials in the same work session. Tutorials promote `dev` → `main`
  only when a release cut makes them runnable on released wheels.
- The same policy applies to every stack package's own tutorials:
  main/master ↔ that package's pip release; dev-state branch
  (dev/spline/gpu_backend) ↔ the development APIs.

## Repo layout (dev branch)

- `tutorials/NN_*.ipynb` — informational track (00–08), committed WITH
  executed outputs (the lisatools Sphinx docs render them without
  re-executing).
- `tutorials/further/answers/XN_*-complete.ipynb` — exercise answer keys
  (SOURCE OF TRUTH, committed executed).
- `tutorials/further/XN_*.ipynb` — student versions, GENERATED by
  `python scripts/remove_answers.py` (never hand-edit).
- `tutorials/STYLE.md` — the authoring contract (cell skeleton,
  Task/Question format, `# clear`/`# clear-line` markers, runtime and
  memory budgets, docstring-currency rule). Read it before touching any
  notebook.
- `scripts/run_all.sh` — sequential execution harness (one kernel at a
  time, niced, OMP=1, per-notebook time + peak RSS). Run it before every
  commit that touches notebooks.
- `tutorials/doc_audit_deferred.md` — ledger of stale docs found OUTSIDE
  the tutorial/stock-pipeline scope (deferred; do not fix them now).

`main` keeps the original workshop layout (`tutorials/Tutorial0-6.ipynb` +
challenge + `tutorials/tutorial_answers/`) — do not port the dev layout
back to main.

## Execution policy

Everything runs on laptop CPU with `OMP_NUM_THREADS=1` (and the other
thread pins) — see the MPI-only/no-OMP sprint rule in LAT's conventions.
Never execute notebooks in parallel; keep peak RSS to a few GB per
notebook.
